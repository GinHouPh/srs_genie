Thank you for purchasing SRS Genie — the Autonomous Specification Engineering Platform and AI-Ready Task Decomposer. This complete guide will walk you through deploying your software, configuring database connectivity, setting up AI API providers, activating your license, and onboarding clients in under 10 minutes.

01 What's in Your Package

Your purchase archive contains the entire production distribution, ready to deploy directly without requiring node build tools, as well as developer source files.

Production Web Bundle

Compiled React 19 + TypeScript single-page application located in dist/ with production asset hashing, gzip/brotli compression support, and deep URL routing rules.

Self-Migrating PHP REST API

Zero manual SQL import headaches. The lightweight, secure PHP 8.1+ REST API in public/api/ automatically migrates all tables, indices, and default seed records on boot.

Multi-AI Provider Engine

Direct support for Google Gemini 2.5/2.0, OpenAI GPT-4o, Anthropic Claude 3.7 Sonnet, DeepSeek-V3/R1, Groq, Ollama, and custom OpenAI-compatible endpoints with client-side failover.

MCP Server Protocol Gateway

Hardened Model Context Protocol (MCP) STDIO server in mcp/server.mjs with SHA-256 token authorization, path-traversal guards, and rate limiting for Cursor & Claude Desktop.

Fast-Track Guarantee

You do not need to install Node.js or run npm build on your production hosting server if you deploy the pre-compiled dist/ bundle. Simply copy the files and set your database connection!

05 Track 1: cPanel / Shared Hosting Deployment

Recommended for Hostinger, cPanel, StackCP, Serverbyt, Bluehost, Namecheap, and standard Apache/LiteSpeed hosts.

Step 1: Create MySQL Database in cPanel

  1. Log into your cPanel dashboard.
  2. Under Databases, click MySQL Database Wizard (or MySQL Databases).
  3. Create a database name (e.g. cpaneluser_srsgenie).
  4. Create a database user and generate a strong password (e.g. cpaneluser_srsuser).
  5. Assign the user to the database and check ALL PRIVILEGES. Click Make Changes.
  6. Note down the Database Name, User, and Password.

Step 2: Upload Application Files

Open cPanel File Manager. Navigate to your target directory:

  • For primary domain: navigate to public_html/
  • For a subdomain (e.g. srs.yourdomain.com): navigate to the subdomain's document root.

Upload the distribution zip (dist.zip or compiled package) and extract it. Ensure the folder structure matches:

Folder Structure 
public_html/
├── .htaccess                 # Essential Apache URL routing & security rules
├── index.html                # Vite React Single Page Application entry
├── assets/                   # Compiled JS, CSS, and SVG chunks
├── api/                      # PHP REST API endpoints
│   ├── config.php            # <-- EDIT THIS with your DB credentials!
│   ├── db.php                # Database PDO engine & auto-migration
│   ├── auth.php              # Authentication & password management
│   ├── health.php            # Diagnostics & auto-migration trigger
│   ├── license.php           # Envato / Agape License client
│   ├── license_check.php     # Cryptographic domain & signature check
│   ├── projects.php          # Specification projects store
│   ├── saas.php              # SaaS settings, AI keys & billing
│   └── cashfree.php          # Payment gateway order & webhook handler
└── mcp/                      # Model Context Protocol server for IDEs
    └── server.mjs            # Hardened STDIO MCP server

Step 3: Configure Database Connection

Open api/config.php in the File Manager Code Editor and enter your MySQL details:

php (api/config.php) 
<?php
/**
 * SRS Genie - Database Configuration
 */
return [
    'db_host'    => getenv('DB_HOST') ?: 'localhost',            // Usually 'localhost' or '127.0.0.1'
    'db_name'    => getenv('DB_NAME') ?: 'cpaneluser_srsgenie',  // Your MySQL Database Name
    'db_user'    => getenv('DB_USER') ?: 'cpaneluser_srsuser',   // Your MySQL Database User
    'db_pass'    => getenv('DB_PASS') ?: 'YourStrongPassword123!',// Your MySQL Database Password
    'db_charset' => 'utf8mb4'
];

Step 4: Verify Apache .htaccess File

Verify that .htaccess is present in your web root. In cPanel, click Settings (top right) > check Show Hidden Files (dotfiles) to see it:

# MIME Types & Headers

<IfModule mod_headers.c>

06 Track 2: Ubuntu VPS Deployment (Nginx + PHP-FPM)

Full step-by-step terminal instructions for Ubuntu 22.04 / 24.04 LTS servers (AWS EC2, DigitalOcean, Hetzner, Linode, Vultr):

Step 1: Install Nginx, PHP 8.2 & MySQL Server

bash (Terminal) 
# Update package repositories
sudo apt update && sudo apt upgrade -y

# Install Nginx, MySQL Server, and PHP 8.2 with extensions
sudo apt install -y nginx mysql-server certbot python3-certbot-nginx \
  php8.2-fpm php8.2-mysql php8.2-curl php8.2-mbstring php8.2-xml \
  php8.2-zip php8.2-gd php8.2-intl unzip git curl

# Verify PHP-FPM status
sudo systemctl status php8.2-fpm --no-pager

Step 2: Create MySQL Database and User

sql (MySQL Terminal) 
sudo mysql

-- Create database with utf8mb4 collation
CREATE DATABASE srsgenie_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- Create secure user
CREATE USER 'srsgenie_user'@'localhost' IDENTIFIED BY 'PutStrongPasswordHere$2026!';

-- Grant privileges
GRANT ALL PRIVILEGES ON srsgenie_db.* TO 'srsgenie_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;

Step 3: Setup Web Root and Permissions

bash (Terminal) 
# Create application directory
sudo mkdir -p /var/www/srsgenie

# Upload or copy your SRS Genie files into /var/www/srsgenie
# (If using SCP or Git clone):
# sudo git clone https://github.com/your-repo/srsgenie.git /var/www/srsgenie

# Configure database in config.php
sudo nano /var/www/srsgenie/public/api/config.php

# Assign web permissions to www-data
sudo chown -R www-data:www-data /var/www/srsgenie
sudo chmod -R 755 /var/www/srsgenie

Step 4: Configure Nginx Server Block

Create a new Nginx configuration file: sudo nano /etc/nginx/sites-available/srsgenie.conf

nginx (/etc/nginx/sites-available/srsgenie.conf) 
server {
    listen 80;
    server_name srs.yourdomain.com; # Replace with your actual domain

    root /var/www/srsgenie/dist;     # Or root /var/www/srsgenie if files are in root
    index index.html index.php;

    client_max_body_size 32M;

    # Gzip compression
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;

    # API rewrite rule to PHP API handlers
    location /api/ {
        alias /var/www/srsgenie/public/api/;
        try_files $uri $uri/ @api_rewrite;

        location ~ \.php$ {
            include snippets/fastcgi-php.conf;
            fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
            fastcgi_param SCRIPT_FILENAME $request_filename;
        }
    }

    location @api_rewrite {
        rewrite ^/api/(.*)$ /api/$1.php last;
    }

    # SPA routing for React (Vite)
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache static assets
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Deny hidden files like .env or .git
    location ~ /\. {
        deny all;
    }
}

Step 5: Enable Site & Issue Free SSL Certificate

bash (Terminal) 
# Enable configuration in Nginx
sudo ln -s /etc/nginx/sites-available/srsgenie.conf /etc/nginx/sites-enabled/
sudo nginx -t

# Reload Nginx
sudo systemctl reload nginx

# Install free Let's Encrypt SSL certificate
sudo certbot --nginx -d srs.yourdomain.com

            13 Step 6: Connect IDEs via Model Context Protocol (MCP)

How MCP Integration Works:

When an AI agent needs requirements, it queries the SRS Genie MCP server, which safely reads the .specs/ hierarchy and passes exact architectural context to the AI assistant.
        


        

          

            
            
            
          


          
          

            

              In your project folder, create or edit .cursor/mcp.json (or in Cursor Settings > Features > MCP > Add New MCP Server):

    "srs-genie": {
      "command": "node",
      "args": ["./mcp/server.mjs", "--key=YOUR_MCP_API_KEY"],
      "env": {
        "SRS_MCP_KEY": "YOUR_MCP_API_KEY"
      }
    }
  }
}

            15 Troubleshooting & Frequently Asked Questions
          

        

        

          Solutions to the most common configuration and deployment questions:
        


        

          

            
            

              A 500 error on health.php almost always means the MySQL database credentials in api/config.php are incorrect, or the MySQL user does not have permissions to create tables.
              


              Checklist to resolve:
              
    
                
  • Verify your database host. On shared hosting like cPanel or StackCP, check if your host uses localhost or a specialized host like sdb-xx.hosting.stackcp.net.
    • 
                
  • Verify that you entered the exact database name and database user (including any cPanel prefix like user_dbname).
    • 
                
  • Make sure the user has ALL PRIVILEGES granted in MySQL.
    • 
                
  • Check your server's PHP error log (error_log in the web root or /var/log/nginx/error.log) for the specific PDO exception.
    • 
              

            

          


          

            
            

              This happens when URL rewriting is not active for the React Single Page Application:
